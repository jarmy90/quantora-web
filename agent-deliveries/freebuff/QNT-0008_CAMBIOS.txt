============================================================
Rama: fix/QNT-0008-local-build-portability

OBJETIVO ALCANZADO
------------------
Corregidos los cuatro problemas técnicos detectados en la auditoría local
(QNT-CHECKPOINT), sin tocar lógica de estrategias, métricas, catálogo
comercial, diseño visual, scoring ni datos reales.

1) NORMALIZACIÓN EOL (hashes reproducibles Windows/Linux)
   - Nuevo .gitattributes: eol=lf para texto (*.ts, *.tsx, *.js, *.jsx,
     *.json, *.csv, *.md, *.txt, *.sha256, *.css, *.html, *.yml, *.yaml,
     *.sh) y binary para artefactos (*.zip, *.png, *.jpg, *.jpeg, *.gif,
     *.webp, *.ico, *.pdf, *.woff, *.woff2, *.zip.txt).
   - 22 archivos de evidencia renormalizados a LF (solo EOL; contenido
     lógico idéntico, verificado con `git diff --ignore-cr-at-eol`).
   - Manifests regenerados por el pipeline (hashes calculados sobre LF);
     `strategies:validate` y los tests de intake pasan con 0 errores.
   - La causa raíz era core.autocrlf=true + evidencia commiteada con
     mezcla LF/CRLF, lo que rompía los SHA-256 en checkout Windows.

2) BUILD CSS (~/styles/app.css?url)
   - __root.tsx usaba `import appCss from "~/styles/app.css?url"` con
     alias `~`, que Rollup no resolvía. Se sustituyó por el import
     lateral relativo `../styles/app.css`, el mismo patrón que ya usaban
     las demás rutas. Sin cambios de estilos ni de diseño.

3) TYPECHECK
   - serve.ts (entrypoint Bun) fallaba por falta de tipos Bun
     (`Bun.serve`, `Bun.$`, `Bun.file`, `import.meta.dir`, req implícito).
     Solución canónica: devDependency @types/bun + "bun" en tsconfig types.
   - LegalShell.tsx: import sin uso (ReactNode) eliminado.
   - Resultado: tsc --noEmit = 0 errores.

4) PREVIEW LOCAL
   - `vite dev` (puerto 3000) ahora sirve con HTTP 200: /, /strategies,
     las 4 fichas, /dashboard y /legal/*. Consola del navegador limpia.
     El 404 previo era artefacto de servidor dev obsoleto/caché de
     optimización de dependencias; un arranque limpio sirve SSR completo.
