QNT-0013 · AUTENTICACIÓN Y EXPERIENCIA DE USUARIO (Supabase Auth)
=============================================================================
Rama: feat/QNT-0013-supabase-auth
Base: main (dd4dc85 · incluye QNT-0012C fusionado vía PR #11)

OBJETIVO ALCANZADO
------------------
Base real de autenticación con Supabase Auth (email + contraseña) y sesiones
SSR mediante cookie HttpOnly. El usuario puede registrarse, confirmar correo,
iniciar/cerrar sesión, solicitar recuperación de contraseña y establecer una
nueva. Existe zona protegida /account con estados vacíos honestos. Sin
pagos, licencias, precios ni descargas activadas.

ARQUITECTURA
------------
- Proveedor: Supabase Auth (email + password). PKCE para el callback.
- Sesión: cookie HttpOnly `quantora-auth-token` (SameSite=Lax, Secure en
  prod) con el access token; verificación server-side vía getUser(token).
  Nunca localStorage. Service role NUNCA usado.
- Separación: la app depende de `AuthService` (src/domain/auth/contracts.ts),
  no del SDK. Implementación única: `SupabaseAuthService` (service.ts).
  `fake.ts` es TEST-ONLY.
- Estados de entorno: configured / not_configured / invalid_configuration.
  Sin claves => AUTH_NOT_CONFIGURED (la web funciona y muestra pantalla de
  configuración; el resto del sitio no se bloquea).

RUTAS
-----
/login · /register · /forgot-password · /reset-password · /auth/callback ·
/account (protegida; sin sesión -> redirect a /login con returnTo seguro).
CTA en fichas: "Sign in to save your interest" con returnTo interno validado
(isSafeReturnTo: solo rutas internas, sin open redirects).

RELACIÓN AUTH -> CUSTOMER
-------------------------
db/migrations/0002_customers_auth_user.sql:
customers.auth_user_id uuid UNIQUE REFERENCES auth.users(id) ON DELETE SET NULL
+ índice + RLS preparatorio (comentado, mínimamente permisivo). customer_id
sigue siendo el identificador comercial; auth_user_id es la identidad Supabase.

ENTORNO
-------
.env.example: VITE_SUPABASE_URL, VITE_SUPABASE_PUBLISHABLE_KEY (públicas) y
SUPABASE_SERVICE_ROLE_KEY (server-only, reservada, sin usar). .env/.env.local
ignorados.

@tanstack/react-start-server — el optimizador esbuild no puede resolver los

inyecta el plugin TanStack Start. Sin este fix `vite dev` se rompía tras la
instalación de dependencias (lockfile re-optimizado). El build de producción
